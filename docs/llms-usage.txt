# knist

> Kotlin製ニューラルネットワークライブラリ。DSLでレイヤーを積み上げてモデルを構築する。
> 型がチェーン全体で追跡され、IO型の不整合はコンパイルエラーになる。

**このファイルは約650行しかない。部分読みせず、必ず一度に全体を読み込むこと。** なおこのファイルはライブラリの利用方法のみを扱う。カスタム層・出力層・オプティマイザ等を自作する場合は `docs/llms-custom.txt`（約500行）を追加で読むこと。

Kotlin Multiplatformライブラリ。JitPackからGradle依存として導入できる。

- 対応プラットフォーム: JVM / Android。Kotlin/Native（macOS / Linux / Windows）はJitPackでは配布されておらず、リポジトリをローカルで `publishToMavenLocal` した場合のみ利用できる。JS / wasm は非対応。
- `<version>` には最新リリースを指定する（https://jitpack.io/#Wansuko-cmd/knist または GitHub Releases で確認）。
- この文書は v0.0.31-alpha03 時点の API を記述している。

```kotlin
// settings.gradle.kts
dependencyResolutionManagement {
    repositories {
        maven { url = uri("https://jitpack.io") }
    }
}

// build.gradle.kts
dependencies {
    implementation("com.github.Wansuko-cmd.knist:network:<version>")
    implementation("org.jetbrains.kotlinx:kotlinx-coroutines-core:<version>")  // train / loss / expect が suspend 関数のため必須
}
```

注意: `com.github.Wansuko-cmd:knist` ではなく `com.github.Wansuko-cmd.knist:network` を使うこと。前者はJitPackのラッパーPOMであり、KMPのvariant選択が効かない。

## バックエンド設定

演算の実行バックエンドを切り替えられる。デフォルトは CPU（Rust ネイティブ）。追加の Gradle 依存は不要（`network` 依存が `io-type` → `buffer` を経由してすべてのバックエンドを含む）。

| バックエンド | import | 説明 | フォールバック |
|------------|--------|------|--------------|
| `cpu` | `com.wsr.knist.cpu.cpu` | Rust ネイティブ CPU 実装 | KotlinBackend |
| `gpu` | `com.wsr.knist.gpu.gpu` | WebGPU（wgpu）GPU 実装 | KotlinBackend |
| `KotlinBackend` | `com.wsr.knist.base.KotlinBackend` | 純 Kotlin 実装 | — |

切り替えは学習・推論の前に一度 `Backend.set()` を呼び出す。

```kotlin
import com.wsr.knist.Backend
import com.wsr.knist.gpu.gpu

Backend.set(gpu)
```

`cpu` / `gpu` はネイティブライブラリが利用不可の環境では自動的に `KotlinBackend` にフォールバックする。
※ GPUは不安定で、稀に実行速度が非常に遅くなることがある。その際にはCPUに書き換える。

## 基本的な使い方

### モデル構築

`NetworkBuilder` のDSLでレイヤーを積み上げる。最後に出力層（`softmaxWithLoss` 等）を呼ぶと `Network` オブジェクトが得られる。

`Network<I, O>` の `I`・`O` はバッチ全体の型。`Converter<T>` の `T` がそのままバッチ型として使われる。

```kotlin
// Batch<IOType.D1> を直接渡す場合（RawD1 を使う）
val network: Network<Batch<IOType.D1>, Batch<IOType.D1>> = NetworkBuilder
    .inputD1(32, optimizer = AdamW(Scheduler.Fix(0.001f)), initializer = He())
    .affine(neuron = 256).bias().reLU()
    .affine(neuron = 10)
    .meanSquare()

// カスタムConverter を使う場合（例: List<List<Float>> → D2）
val network: Network<List<List<Float>>, List<Int>> = NetworkBuilder
    .inputD2(converter = MyPixelConverter(28, 28), optimizer = AdamW(Scheduler.Fix(0.001f)), initializer = He())
    .reshapeToD1()
    .affine(neuron = 10)
    .softmaxWithLoss(converter = { MyLabelConverter(inputI) })
```

### Raw入力用の Batch の作り方

`RawD1` 等を使う場合、入力の `Batch<IOType.Dx>` は FloatArray から直接構築する。`value` にはバッチ全サンプルを行優先で連結した配列（長さ = バッチサイズ × 1サンプルの要素数）を渡す。

```kotlin
import com.wsr.knist.batch.Batch
import com.wsr.knist.core.IOType
import com.wsr.knist.base.data.DataBuffer

// バッチサイズ64・1サンプルの形状 [32] の D1 入力バッチ
val inputs: Batch<IOType.D1> = Batch(
    size = 64,
    shape = listOf(32),
    value = DataBuffer.create(FloatArray(64 * 32) { /* 値 */ 0f }),
)
// D2 は shape = listOf(i, j)、D3 は shape = listOf(i, j, k)
```

### 学習

`I` 自体がバッチ型なので、バッチ単位で渡す。`train` / `loss` / `expect` はすべて `suspend` 関数であり、コルーチンスコープ内から呼ぶことを想定している。いずれも `dispatcher` 引数（デフォルト: `Dispatchers.Default`）を取る。

`Network` は内部の Mutex により保護されておりスレッドセーフだが、`train` / `loss` / `expect` は相互排他である。複数コルーチンから並列に呼んでも実行は1件ずつ直列化される（推論のみの場合も同様）。

```kotlin
// suspend スコープ内での典型的な使い方
coroutineScope.launch {
    // ラベルを直接渡す（戻り値は IOType.D0.Global）
    val loss: IOType.D0.Global = network.train(input = inputs, label = labels)
    val lossValue: Float = loss.unwrap()  // Float として読み出す場合

    // ラベルジェネレータ（現在の出力を受け取って目標値を返す。DQN の Bellman ターゲット等に使える）
    val loss: IOType.D0.Global = network.train(input = inputs) { currentOutput -> modifiedOutput }
}
```

典型的なエポックループ（カスタム Converter 使用時の例。`I` = `List<List<Float>>`, `O` = `List<Int>`）:

```kotlin
runBlocking {
    repeat(epochs) {
        dataset.shuffled().chunked(batchSize).forEach { chunk ->
            network.train(
                input = chunk.map { it.pixels },
                label = chunk.map { it.label },
            )
        }
    }
}
```

### loss計算（逆伝播なし）

`train()` と同じ2バリアントがある。重みを更新せずに損失だけ得たい場合に使う。
順伝播は推論時と同じ経路で行われる（dropout はパススルーになる等）。

```kotlin
val loss: IOType.D0.Global = network.loss(input = inputs, label = labels)
val loss: IOType.D0.Global = network.loss(input = inputs) { currentOutput -> modifiedOutput }
```

### 推論

```kotlin
val result: O = network.expect(input = inputs)  // suspend。inputs: I（バッチ型）
```

戻り値は出力層の結果（`softmaxWithLoss` なら softmax 後の確率分布）を `Converter.decode` に通したもの。生の確率分布を使いたい場合（温度・top-k 等のサンプリングを自前で行う場合など）は、decode がそれを返すように Converter を実装する。

## IOType 定義

| 型 | 形状 | 意味 |
|----|------|------|
| `D0` | スカラー | 損失値など単一値 |
| `D1(i)` | [i] | ベクトル |
| `D2(i, j)` | [i, j] | 行列 |
| `D3(i, j, k)` | [i, j, k] | 3次元テンソル |

各次元型には `Global` と `Local` の2サブクラスがあるが、**ライブラリを利用するだけなら区別を意識する必要はない**。`train` / `loss` 等の API が返すのはすべて `Global`。`Local` はカスタム層等を実装する場合にのみ現れる（`docs/llms-custom.txt` を参照）。

`IOType` をユーザーコードで明示的に解放する必要はない。解放は `IOScope` の終了（ライブラリ内部で自動的に行われる）か、GC による回収のいずれかで行われる。

`IOType.D0.Global` から `Float` を取り出すには `.unwrap()` を使う（import: `com.wsr.knist.core.unwrap`）:

```kotlin
val lossValue: Float = loss.unwrap()
```

## 全層一覧（import パス付き）

重みを持つレイヤーの factory 関数（`affine` / `bias` / `scale` / `convD1` / `convD2` / `attention` / `tokenEmbedding` / `positionEmbedding` / `minMaxNorm`）は、表に記載の引数に加えて `optimizer` / `initializer` を省略可能引数として取り、層ごとに個別指定できる（詳細は Optimizer 節）。

### 畳み込み・プーリング

| 関数 | import | 入力 | 出力 | デフォルト値 |
|------|--------|------|------|-------------|
| `convD1(filter, kernel, stride?, padding?)` | `com.wsr.knist.network.process.compute.conv.convD1` | D2(i, j) | D2(filter, outJ) | stride=1, padding=0 |
| `convD2(filter, kernel, stride?, padding?)` | `com.wsr.knist.network.process.compute.conv.convD2` | D3(i, j, k) | D3(filter, outJ, outK) | stride=1, padding=0 |
| `maxPool(size, padding?)` | `com.wsr.knist.network.process.compute.pool.maxPool` | D2(i, j) | D2(i, outJ) | padding=0 |
| `maxPool(size, padding?)` | `com.wsr.knist.network.process.compute.pool.maxPool` | D3(i, j, k) | D3(i, outJ, outK) | padding=0 |

制約: `(size - kernel + 2 * padding) % stride == 0` でなければ実行時エラー
制約: maxPool は `(j + 2*padding - size) % size == 0` でなければ実行時エラー（D3 は j・k 両方）

### 全結合・変換系

| 関数 | import | 入力 | 出力 |
|------|--------|------|------|
| `affine(neuron)` | `com.wsr.knist.network.process.compute.affine.affine` | D1(n) | D1(neuron) |
| `affine(neuron)` | `com.wsr.knist.network.process.compute.affine.affine` | D2(i, j) | D2(i, neuron) |
| `bias()` | `com.wsr.knist.network.process.compute.bias.d1.bias` | D1(n) | D1(n) |
| `bias(axis?)` | `com.wsr.knist.network.process.compute.bias.d2.bias` | D2(i, j) | D2(i, j) |
| `bias(axis?)` | `com.wsr.knist.network.process.compute.bias.d3.bias` | D3(i, j, k) | D3(i, j, k) |
| `scale()` | `com.wsr.knist.network.process.compute.scale.d1.scale` | D1(n) | D1(n) |
| `scale(axis?)` | `com.wsr.knist.network.process.compute.scale.d2.scale` | D2(i, j) | D2(i, j) |
| `scale(axis?)` | `com.wsr.knist.network.process.compute.scale.d3.scale` | D3(i, j, k) | D3(i, j, k) |

D2/D3 の `bias` / `scale` の `axis`: null=全体, 0=i方向, 1=j方向（D3はさらに 2=k方向）

D1とD2で同名関数を両方 import する場合、Kotlin はレシーバー型で自動解決する:
```kotlin
import com.wsr.knist.network.process.compute.bias.d1.bias
import com.wsr.knist.network.process.compute.bias.d2.bias  // 同名でも競合しない
```

### Attention

| 関数 | import | 入力 | 出力 |
|------|--------|------|------|
| `attention(numOfHeads, dim?, biases?, optimizer?, initializer?)` | `com.wsr.knist.network.process.compute.attention.attention` | D2(i, j) | D2(i, j) |

デフォルト値: `dim = inputJ / numOfHeads`（整数除算）, `biases = { this }`（バイアスなし）
制約: j は numOfHeads で割り切れるようにすること。割り切れなくてもエラーにはならないが、デフォルトの `dim` が切り捨てられ、内部次元（numOfHeads × dim）が j より小さいモデルが黙って出来上がる
Self-attention 専用（Q・K・V はすべて同一の入力から計算される）。Q/K/V/O の射影にバイアス項は付かない。

`biases` ラムダで `AttentionBiasD2Builder` をチェーンして適用するバイアスを指定する。

| メソッド | 説明 |
|---------|------|
| `causal()` | Causal mask（未来トークンへの注目を -1e9 でマスク） |
| `mask(value: Float)` | Padding mask（ネットワークの最初の入力のうち値が `value` の位置を -1e9 でマスク） |
| `alibi()` | ALiBi（ヘッドごとに異なる傾きで距離に比例した罰則を加算） |

`mask` はネットワークの最初の入力（`Converter.encode` の結果。Context 経由で参照される）が **D1 のトークンID列**であり、かつその長さが attention の系列長と一致している場合のみ使える。`inputD2` / `inputD3` 始まりのモデルでは使用できない（実行時エラーになる）。

```kotlin
// Causal のみ
.attention(numOfHeads = 8, biases = { causal() })

// Causal + Padding mask
.attention(numOfHeads = 8, biases = { causal().mask(0f) })

// ALiBi + Padding mask
.attention(numOfHeads = 8, biases = { alibi().mask(0f) })
```

### 位置エンコーディング

| 関数 | import | 入力 | 出力 | デフォルト値 |
|------|--------|------|------|-------------|
| ~~`roPE(waveLength?)`~~ | `com.wsr.knist.network.process.compute.position.roPE` | D2(i, j) | D2(i, j) | waveLength=10000f |
| `positionEncode(waveLength?)` | `com.wsr.knist.network.process.compute.position.positionEncode` | D2(i, j) | D2(i, j) | waveLength=10000f |

**`roPE` は Deprecated**: RoPE は Attention 内部で Q・K に適用するのが正しい設計だが、現実装は入力全体に適用しており非推奨。Attention 内部に RoPE を適用する手段は現状無いため、位置情報には `positionEncode` / `positionEmbedding`（または attention の `alibi()`）を使うこと。

注意: `positionEmbedding` はサイズを変えない学習可能な位置バイアスを加算するだけ。

### Dropout

| 関数 | import | デフォルト値 |
|------|--------|-------------|
| `dropout(ratio, seed?)` | `com.wsr.knist.network.process.compute.dropout.dropout` | seed=null |

`ratio` は**保持確率**（1.0 = 全ユニットを残す）。PyTorch の `p`（ドロップ率）とは意味が**逆**なので注意。`dropout(ratio = 0.9f)` は 10% のユニットを落とす。推論時（`expect` / `loss`）はパススルー。

### デバッグ

| 関数 | import |
|------|--------|
| `debug(onInput?, onDelta?)` | `com.wsr.knist.network.process.compute.debug.debug` |

値・形状を変えないパススルー層（D1→D1, D2→D2, D3→D3）。import 1行で全次元に対応する。コールバックで途中のテンソルを観察できる。

- `onInput`：順伝播時（`expect` / `train` 両方）に入力テンソルを受け取る
- `onDelta`：`train` 時に勾配（delta）を受け取る

注意: JSON / CBOR でシリアライズするとラムダはリセットされる（`@Transient`）。

### スキップ接続

| 関数 | import | 制約 |
|------|--------|------|
| `skip { ... }` | `com.wsr.knist.network.process.compute.skip.skip` | ブロック内の出力が入力と同サイズであること |

skip ブロックの**最終出力**が入力と同じ次元・同じ形状であればよい。ブロック内で `reshapeToD1()` 等により一時的に次元を変えて元の次元に戻す構成もサポートされる（最終レイヤーが対象次元の Compute または Reshape 系であること）。対応外の型でブロックが終わる場合は構築時にエラーになる。ブロックが空の場合（何もレイヤーが追加されない場合）は `skip` 自体が何も追加せず、入力をそのまま返す。

| `reshapeToD1()` | `com.wsr.knist.network.process.reshape.reshape.reshapeToD1` | D3(i, j, k) | D1(i×j×k) | — |
| `reshapeToD2(i?, j?)` | `com.wsr.knist.network.process.reshape.reshape.reshapeToD2` | D1(n) | D2(i, j) | i=1, j=inputI |
| `reshapeToD2(i, j)` | `com.wsr.knist.network.process.reshape.reshape.reshapeToD2` | D3(i, j, k) | D2(i, j) | — |

| `reshapeToD3(i?, j?, k?)` | `com.wsr.knist.network.process.reshape.reshape.reshapeToD3` | D2(i, j) | D3(i, j, k) | i=1, j=inputI, k=inputJ |
| `globalAverageToD1()` | `com.wsr.knist.network.process.reshape.gad.globalAverageToD1` | D2(i, j) | D1(i) | — |
| `globalAverageToD1()` | `com.wsr.knist.network.process.reshape.gad.globalAverageToD1` | D3(i, j, k) | D1(i) | — |
| `globalAverageToD2()` | `com.wsr.knist.network.process.reshape.gad.globalAverageToD2` | D3(i, j, k) | D2(j, k) | — |
| `tokenEmbedding(vocabSize, tokenSize)` | `com.wsr.knist.network.process.reshape.token.tokenEmbedding` | D1(i) | D2(i, tokenSize) | — |

reshapeToD2 (D1→D2) の制約: `i * j == inputI` でなければ実行時エラー
reshapeToD2 (D3→D2) の制約: `inputI * inputJ * inputK == i * j` でなければ実行時エラー
reshapeToD3 (D1→D3) の制約: `i * j * k == inputI` でなければ実行時エラー
reshapeToD3 (D2→D3) の制約: `i * j * k == inputI * inputJ` でなければ実行時エラー

| `softmaxWithLoss(converter?, temperature?)` | `com.wsr.knist.network.output.softmax.softmaxWithLoss` | D2(i, j) | `Network<I, Label>` |
| `sigmoidWithLoss()` | `com.wsr.knist.network.output.sigmoid.sigmoidWithLoss` | D1(n) | `Network<I, IOType.D1>` |
| `sigmoidWithLoss(converter)` | 同上 | D1(n) | `Network<I, O>` |
| `meanSquare()` | `com.wsr.knist.network.output.mean.meanSquare` | D1(n) | `Network<I, IOType.D1>` |
| `meanSquare(converter)` | 同上 | D1(n) | `Network<I, O>` |

`softmaxWithLoss` デフォルト値: `temperature=1f`
`temperature` は**構築時に固定**され、学習・推論の両方の softmax に適用される。構築後・読み込み後に変更する手段は無いため、推論時に温度を変えたい場合はモデルを構築し直す必要がある。
`softmaxWithLoss` の `converter` ラムダ内では `inputI` が参照可能

ラベルのある行を丸ごとロス計算から除外したい場合（パディング等）は、`maskValue` のような専用パラメータは無く、Converter の `encode` 側でその行を全ゼロベクトルとして出力する。**D2 版の** `softmaxWithLoss` は内部でラベル行の合計が 0 かどうかを見て自動的に除外する（D1 版にはこの除外機構は無い）。

## Converter（入出力変換器）

ユーザーデータと内部 IOType の変換を担う。`inputD1` 等のファクトリ関数と、`softmaxWithLoss` 等の出力層関数の両方に渡せる。

`Converter<T>` の型パラメータ `T` はバッチ全体の型。`encode(input: T)` がバッチを受け取り、`decode` がバッチを返す。これがそのまま `Network<I, O>` の `I`・`O` になる。

### 組み込みConverter

| クラス | import | 入力型(T) | 次元 |
|--------|--------|----------|------|
| `RawD1(outputI)` | `com.wsr.knist.network.converter.raw.RawD1` | `Batch<IOType.D1>` | D1 |
| `RawD2(outputI, outputJ)` | `com.wsr.knist.network.converter.raw.RawD2` | `Batch<IOType.D2>` | D2 |
| `RawD3(outputI, outputJ, outputK)` | `com.wsr.knist.network.converter.raw.RawD3` | `Batch<IOType.D3>` | D3 |

Raw 系は変換なし（`Batch<IOType.Dx>` をそのまま渡す）。カスタム型を使う場合はカスタム Converter を実装する。

### カスタムConverter実装に必要な import

```kotlin
import com.wsr.knist.batch.Batch                  // Batch<T>
import com.wsr.knist.batch.shape.toList           // Batch.toList()
import com.wsr.knist.core.IOType                  // IOType.D1 / D2 / D3
import com.wsr.knist.batch.reduction.maxIndex     // Batch<IOType.D1>.maxIndex() 等（decode で使う。IOType 単体用は com.wsr.knist.core.reduction.maxIndex）
import com.wsr.knist.base.data.DataBuffer         // DataBuffer.create(floatArray)
import com.wsr.knist.network.converter.Converter  // Converter.D1<T> / D2<T>
```

### カスタムConverter実装例

**出力ラベル用（List<Int> → One-hot）**

T はバッチ型なので `List<Int>`（バッチ分のラベルをまとめて受け取る）。

```kotlin
@Serializable
data class LabelConverter(override val outputI: Int) : Converter.D1<List<Int>>() {
    override fun encode(input: List<Int>): Batch<IOType.D1> {
        val value = FloatArray(input.size * outputI)
        input.forEachIndexed { batchIndex, label ->
            value[batchIndex * outputI + label] = 1f
        }
        return Batch(size = input.size, shape = listOf(outputI), value = DataBuffer.create(value))
    }
    override fun decode(input: Batch<IOType.D1>): List<Int> =
        input.maxIndex().value.toFloatArray().map { it.toInt() }
}
```

**入力特徴量用（List<List<Float>> → D2）**

```kotlin
@Serializable
data class PixelConverter(override val outputI: Int, override val outputJ: Int) : Converter.D2<List<List<Float>>>() {
    override fun encode(input: List<List<Float>>): Batch<IOType.D2> {
        val value = input.flatten().toFloatArray()
        return Batch(size = input.size, shape = listOf(outputI, outputJ), value = DataBuffer.create(value))
    }
    override fun decode(input: Batch<IOType.D2>): List<List<Float>> =
        input.value.toFloatArray().toList().chunked(outputI * outputJ)
}
```

保存・読み込みを使う場合は `@Serializable` を付けて登録する（ビルド設定は「モデルの保存・読み込み」節を参照）:
```kotlin
NetworkSerializer.apply { register(LabelConverter::class) }
```

## Optimizer

| クラス | import | 追加パラメータ |
|--------|--------|--------------|
| `Sgd(scheduler)` | `com.wsr.knist.network.optimizer.sgd.Sgd` | — |
| `Momentum(scheduler, momentum?)` | `com.wsr.knist.network.optimizer.momentum.Momentum` | momentum=0.9f |
| `RmsProp(scheduler, rms?)` | `com.wsr.knist.network.optimizer.rms.RmsProp` | rms=0.9f |
| `Adam(scheduler, momentum?, rms?)` | `com.wsr.knist.network.optimizer.adam.Adam` | momentum=0.9f, rms=0.999f |
| `AdamW(scheduler, momentum?, rms?, decay?)` | `com.wsr.knist.network.optimizer.adam.AdamW` | momentum=0.9f, rms=0.999f, decay=0.01f |

共通オプション:

- `maxNorm`: 勾配クリッピング。勾配の L2 ノルムが `maxNorm` を超えた場合にスケールダウンする
- `stepUnit`: Scheduler に渡す step の進行単位。重み更新 `stepUnit` 回ごとに Scheduler の step が 1 進む。**勾配累積ではない**（重みの更新自体は毎回行われ、学習率スケジュールの進行だけが遅くなる）

Optimizer / Initializer は `inputDx` で渡したものがデフォルトとして全層に配られるが、学習可能なレイヤーの factory 関数（`affine` / `bias` / `scale` / `convD1` / `convD2` / `attention` / `tokenEmbedding` / `positionEmbedding` / `minMaxNorm`）は `optimizer` / `initializer` 引数で層ごとに上書きできる。なお `bias` の initializer デフォルトは `Fixed(0f)`、`scale` / `minMaxNorm` は `Fixed(1f)`。

`AdamW` の `decay` は bias / scale を含む**全パラメータに一律に適用される**。特定の層を weight decay から除外したい場合は、その層の `optimizer` 引数に decay の無い Optimizer（`Adam` 等）を個別に渡す。

### Scheduler

| クラス | import | 説明 |
|--------|--------|------|
| `Scheduler.Fix(rate)` | `com.wsr.knist.network.optimizer.Scheduler` | 固定学習率 |
| `Scheduler.Step(rate, gamma, stepCount)` | 同上 | Nステップごとに rate *= gamma |
| `Scheduler.MultiStep(rate, gamma, milestones)` | 同上 | 指定ステップで rate *= gamma |
| `Scheduler.CosineAnnealing(minRate, maxRate, stepSize, warmUp, initialRate)` | 同上 | 線形ウォームアップ→コサインアニーリング |

Scheduler が受け取る step は「そのパラメータの重み更新回数（÷ `stepUnit`）」で、パラメータごとに独立してカウントされる。全パラメータは `train()` 1回につき1回更新されるため、実用上は「`train()` の呼び出し回数」と読み替えてよい（`stepSize` / `warmUp` / `stepCount` / `milestones` は train 回数を基準に設定する）。

## モデルの保存・読み込み

`toJson()` / `toCbor()` は `Network` のメンバー関数、`fromJson()` / `fromCbor()` は `Network.Companion` のコンパニオン関数。いずれも import 不要。

保存されるのはモデル構造・重みに加えて、**Optimizer の内部状態（Adam のモーメント等）と Scheduler の進行位置**も含まれる。読み込み後に学習を再開すると保存時のスケジュールの続きから進む。構築後・読み込み後に学習率や Optimizer を差し替える手段は現状無い（変更したい場合はモデルを構築し直す）。

`fromJson` / `fromCbor` の型パラメータ `I`・`O` は実行時に検証されない。保存時と異なる型を指定しても読み込み自体は成功し、`expect` / `train` の呼び出し時に ClassCastException になるため注意。

カスタムConverterを使っている場合は保存前に登録が必要。

### カスタムConverterを保存する場合のビルド設定

組み込みConverter（`RawD1` 等）のみ使う場合は不要。カスタムConverterを保存・読み込みする場合のみ、以下の設定が必要。

```kotlin
// build.gradle.kts
plugins {
    kotlin("plugin.serialization")
}

dependencies {
    implementation("org.jetbrains.kotlinx:kotlinx-serialization-core:<version>")
}
```

設定後、カスタムConverter に `@Serializable` を付けて登録する。登録はアプリ起動時などに**各クラスにつき一度だけ**行えばよい（モデルを生成するたびに呼ぶ必要はない）：

```kotlin
import com.wsr.knist.network.NetworkSerializer

NetworkSerializer.apply {
    register(MyConverter::class)  // カスタムConverterのみ登録。組み込みは不要
}
```

### JSON形式（テキスト）

```kotlin
// 保存
val json: String = network.toJson()

// 読み込み
val network: Network<I, O> = Network.fromJson(json)
```

### JSON形式（okio BufferedSink/Source）

```kotlin
// 保存
network.toJson(sink)

// 読み込み
val network: Network<I, O> = Network.fromJson(source)
```

### CBOR形式（バイナリ）

```kotlin
// 保存
val bytes: ByteArray = network.toCbor()
network.toCbor(sink)  // Sink版

// 読み込み
val network: Network<I, O> = Network.fromCbor(bytes)
val network: Network<I, O> = Network.fromCbor(source)  // Source版
```

### クローン

```kotlin
val copy: Network<I, O> = network.clone()
```

内部で CBOR シリアライズ→デシリアライズを行う。重みを含む完全なコピーが得られる。カスタム Converter を使う場合は事前に `NetworkSerializer.register()` が必要。

## 典型的な構成パターンとIOの流れ

完全に動作するコードはリポジトリの `sample/` にある:

- MNIST（3層MLP）: `sample/src/commonMain/kotlin/dataset/mnist/MnistUtils.kt`（`PixelConverter` / `LabelConverter` の実装は同ディレクトリの `MnistConverter.kt`）
- TinyStories（Transformer言語モデル）: `sample/src/commonMain/kotlin/dataset/stories/TinyStoriesUtils.kt`（`WordsD1` / `WordD2` の実装も同ディレクトリ）

### MLP（全結合分類）

```
inputD1(converter, optimizer, initializer)  → D1(n)
  → affine(256) → bias() → reLU()          → D1(256)
  → affine(10)                              → D1(10)
  → softmaxWithLoss(converter = { ... })   → Network<Input, Label>
```

### 画像分類（CNN）

`PixelConverter` / `LabelConverter` はカスタム実装（Converter実装例を参照）。

```
inputD2(PixelConverter(28,28), ...)         → D2(28, 28)   // Network<List<List<Float>>, List<Int>>
  → convD1(32, kernel=3, padding=1)         → D2(32, 28)   // outY=(28-3+2)/1+1=28
  → bias() → reLU()
  → maxPool(size=2)                         → D2(32, 14)   // 28/2=14
  → convD1(64, kernel=3, padding=1)         → D2(64, 14)
  → bias() → reLU()
  → maxPool(size=2)                         → D2(64,  7)
  → reshapeToD1()                           → D1(448)      // 64*7=448
  → layerNorm() → affine(128) → bias() → reLU()
  → affine(10)
  → softmaxWithLoss(converter = { LabelConverter(inputI) })
```

### Transformer言語モデル

`WordsD1` / `WordD2` はカスタム実装（組み込みには含まれない）。

```
wordsD1(maxLength=128, words=..., ...)      → D1(128)      // Network<List<List<String>>, List<List<String>>>
  → tokenEmbedding(vocabSize=3000, 256)     → D2(128, 256)
  → positionEmbedding()
  → repeat(4) {
      skip { layerNorm(1).scale(1).bias(1).attention(4, biases = { causal() }).dropout(0.9f) }
      skip { layerNorm(1).scale(1).bias(1).affine(1024).bias(1).swish().affine(256).bias(1).dropout(0.9f) }
    }
  → layerNorm(1).scale(1).bias(1)
  → affine(3000)
  → softmaxWithLoss(converter = { WordD2(words, 128, 1) })
```

## IOScope

`IOScope` は演算中の中間バッファのライフタイムを管理する内部機構。学習・推論の内部で自動的に使われるため、**ライブラリを利用するだけなら意識する必要はない**。カスタム層（`Compute`）・出力層（`Output`）・オプティマイザ（`Optimizer`）を実装する場合は `docs/llms-custom.txt` を参照。
